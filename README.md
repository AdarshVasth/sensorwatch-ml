# SensorWatch ML

SensorWatch scores machine temperature, vibration, and motor current against a simulated operating baseline. Try a preset or enter a reading in the local web demo to see the anomaly score and review flag. Everything runs locally after dependency installation.

## Quick start

Requires Python 3.11 or newer. Tested with Python 3.12 and scikit-learn 1.8.0.

```bash
git clone https://github.com/AdarshVasth/sensorwatch-ml.git
cd sensorwatch-ml
python -m venv .venv
```

Activate with `source .venv/bin/activate` on macOS/Linux or `.venv\Scripts\Activate.ps1` in Windows PowerShell. Then run:

```bash
python -m pip install -r requirements.txt
python -m unittest -v
python model.py
python app.py
```

Open http://127.0.0.1:8000 and try **Typical reading** and **Fault example**. Use Ctrl+C to stop the demo. The two rows in `sample_readings.csv` are generated examples you can copy into the form and redistribute. The larger benchmark is generated by `model.py`; it needs no external dataset.

## Architecture

- `model.py` generates 600 baseline readings and fits a seeded scikit-learn Isolation Forest once per process. A shared latent variable simulates changes in load across the three inputs.
- The benchmark uses separate seeds for 200 normal readings and 60 injected faults. Each benchmark fault shifts one sensor. Labels are used only for evaluation.
- `app.py` serves the HTML form over loopback. The app validates each reading, negates the model's decision margin so that higher means more unusual, and flags positive margins.
- `test_sensorwatch.py` checks holdout separation, score ordering, invalid inputs, evaluation counts, and real HTTP responses.

[Isolation Forest API reference](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html)

## Benchmark and limitations

On the synthetic holdout, this run measured AUROC 0.994 and average precision 0.964. At the model's zero-margin threshold, it flagged 58 of 60 simulated faults and 2 of 200 normal readings.

The synthetic shifts and fault frequency do not represent a specific machine. The score is not a probability or a failure prediction. The demo scores each reading independently and ignores time trends and changes in operating regimes. Real use requires representative historical data, validation across machines and operating conditions, and a threshold selected for the cost of missed faults and false alarms.

## Learn it for an internship interview

1. Trace one reading from the form through validation and `decision_function`. Explain what the sign means.
2. Reduce the synthetic fault shifts, rerun the benchmark, and compare ranking metrics with the false-positive and false-negative counts.
3. Explain why training on the holdout would invalidate the evaluation. Describe how you would split telemetry by time and machine on a real project.
